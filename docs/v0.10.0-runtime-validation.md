# v0.10.0 runtime validation

Production keeps the complete DSH package family exactly pinned to
`0.2.0-rc.2`. The opt-in automatic Session path reuses the released Controller,
artifact codec, DSH persistence, Headless startup and permission admission.
Explicit save/resume remains available with its original workflow contract.

## rc.2 pruner

The production Profile builders and original controlled/native launchers were
executed in independent Node workers against a deterministic local provider.
A real `read` tool produced both successful text and an `ENAMETOOLONG` error;
each exceeded 45,000 characters. The upstream pressure hook actually emitted
`compaction/prune` in all four cases, replacing the tool result with 5,159
characters. The probe fails if no prune occurs. It verifies the original result,
replacement call identity, source sequence, replacement range and error metadata.

Complete raw persistence bytes passed the unchanged production strict decoder
after save, restored into an independent worker, and passed strict decoding again
after continuation. History remained an exact byte prefix; the original write
was not replayed and current read-only/never authority was recomputed. A malformed
prune range was rejected by the unchanged codec. These paths did not demonstrate
an Action defect, so no production pruner patch or validation relaxation was made.

This validates successful/error text-result pressure pruning. It does not claim
provider-confirmed context-overflow, image or subagent coverage, Docker process
isolation, or a live remote model for this specific probe. The release gates
separately exercise real Docker workers and online model runs.

Reproduce with the installed exact dependency graph:

```bash
node scripts/probe-session-production-launchers.mjs --pruner-pressure
node scripts/probe-session-production-launchers.mjs --pruner-error-result
```

## Independent alpha advisory

The existing isolated upstream canary now has an independent non-blocking alpha
channel restricted to `0.2.1-alpha.*`. It records the exact selected version,
phase and failure reason, without modifying production dependencies or claiming
support when a smoke was not executed.

On 2026-10-07 the official registry selected `0.2.1-alpha.1`. Resolution failed
with HTTP 404 for `@deepseek-ai/dsh-invariants@0.2.1-alpha.1`. The report records
`install-failed` and `failedPhase: resolution`; compatibility tests were not reached. This is an
incomplete published package family, not a passing compatibility result. The
production manifest and lock retain `0.2.0-rc.2`; no peer bypass or mixed-family
installation is used.

## Automatic Session boundaries

The [Session contract](session.md) defines matching key identity and workflow
concurrency, current authorization, source binding, generation checks and
failure handling. Use a new workflow path and key when adopting automatic
discovery from an explicit workflow: unkeyed history cannot establish which key
was previously executed. Administrators can delete Actions history; no claim of
permanent first-ever detection is made after that evidence is removed.

The trusted [automatic Session harness](../.github/workflows/session-auto-e2e.yml)
has an independent oracle for hidden memory, raw prefix, generation, current
permission and no replay. Its concurrency probe reads the actual producer job
execution intervals. Local fixtures never substitute for the required independent
Actions runs, complete Core E2E, exact-main CI or formal controlled/native canary.
